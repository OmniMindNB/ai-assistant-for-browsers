# 自定义快捷方式设计

日期：2026-07-29

## 背景

Aluminum 目前在侧边栏中固定提供“总结本页”和“解释划词”两个快捷动作。它们的
展示、提示词和作用范围都写死在界面与 Zustand store 中，用户无法把常用任务
固化成自己的入口，也不能编辑、删除或调整现有两个动作。

本设计把两个现有动作迁移为可配置的默认快捷方式，并允许用户创建同类的自定义
快捷方式。此前已落地的快捷动作双语行为继续保留，参见
`2026-07-28-shortcut-action-response-language-design.md`。

## 目标

- 用户可以新增、编辑、删除和排序快捷方式。
- 每个快捷方式必须选择一种作用范围：
  - 智能读取页面；
  - 选中的文字；
  - 无需页面内容。
- “总结本页”和“解释划词”成为可编辑、可删除的内置默认项。
- 用户可以恢复已删除的默认项，但恢复操作不得覆盖现有配置或排序。
- 设置页保存后，已打开的侧边栏实时更新。
- 继续支持中文和英文界面。

## 非目标

- 不增加浏览器全局键盘快捷键。
- 不支持 `{{selection}}`、`{{page}}` 等提示词模板变量。
- 不增加图标选择、分类、文件夹、搜索或收藏状态。
- 不增加云同步、导入导出、版本历史或定时执行。
- 不改变普通输入框对话、Provider 配置或会话持久化格式。

## 1. 存储与数据模型

快捷方式使用独立的 `chrome.storage.local` 键保存，与现有 Provider `Settings`
对象和 Dexie 对话数据库解耦。数组顺序就是用户定义的显示顺序。

概念数据模型如下：

```ts
type ShortcutScope = 'page' | 'selection' | 'none';

interface ShortcutConfig {
  id: string;
  origin: 'builtin' | 'custom';
  scope: ShortcutScope;
  customized: boolean;
  name?: string;
  prompt?: string;
}
```

约束如下：

- 自定义项必须有非空的 `name` 和 `prompt`，且 `customized` 恒为 `true`。
- 未编辑的内置项使用稳定 ID、默认作用范围和 `customized: false`，不持久化具体
  名称或提示词；运行时从当前语言字典解析。
- 用户保存对内置项的任何编辑时，把表单中当前可见的名称和提示词一并写入记录，
  并设置 `customized: true`。此后该项作为固定文本，不再随界面语言变化。
- 用户恢复默认项时，恢复为 `customized: false`，重新获得自动双语行为。

两个稳定内置 ID 分别表示“总结本页”和“解释划词”。恢复默认时只检查这两个
ID：缺失项按“总结本页、解释划词”的固定顺序追加到现有数组末尾；已存在的内置
项、同名自定义项和其他排序均不改变。

必须区分以下两种存储状态：

- 存储键不存在：首次使用，返回两个未编辑的默认项并将它们写入存储；
- 存储键存在且值为空数组：用户主动删除了全部快捷方式，保持为空，不自动补回。

加载时逐项验证记录。未知作用范围、非法 ID 或缺失必填文本的记录不得执行，也
不得在读取时静默改写原始存储；设置页显示配置错误，侧边栏只展示验证通过的项。

## 2. 设置界面

完整 Options 设置页采用带左侧导航的布局，栏目为：

- 外观；
- 语言；
- 快捷方式；
- 模型。

“快捷方式”栏目顶部提供“新增快捷方式”和“恢复默认”。主体显示可排序列表，
每行包含名称、作用范围、拖动手柄、编辑与删除操作。除拖动外，还提供上移和下移
操作，使键盘用户可以完成相同排序。

新增或编辑表单在列表下方展开，包含：

- 名称；
- 作用范围；
- 提示词。

名称和提示词保存前统一去除首尾空白，空值不得保存。删除操作需要确认。保存
成功后收起表单；保存失败时保留用户输入并显示具体错误。

侧边栏的内嵌设置视图空间较窄，继续使用现有纵向设置结构，并复用同一个快捷方式
管理组件；不在内嵌视图中加入桌面端左侧导航。

## 3. 聊天界面

输入框上方按用户顺序直接展示前 3 个快捷方式。第 4 项起放入“更多”菜单，
菜单入口显示隐藏项数量。快捷方式数组为空时，整行隐藏。

空白对话页中央不再重复展示快捷卡片，只保留产品名称和用途说明。快捷方式无论
对话是否为空，都统一从输入框上方触发。

名称过长时在单行入口中截断显示，但完整名称作为无障碍名称和辅助提示保留。
快捷方式执行期间，所有入口沿用现有 busy 禁用行为。

## 4. 执行流程

侧边栏使用单一的 `runShortcut(shortcut)` 入口取代
`summarizePage()` 与 `explainSelection()` 两条写死路径。点击时先复制当前解析
后的配置作为本轮快照；运行中发生的编辑、删除或排序不影响已经开始的回合。

运行时界面添加一条 `kind: 'action'` 的用户消息，使快捷动作继续保持不可编辑。
普通快捷方式显示其名称；选区类快捷方式显示名称和最多 80 个字符的选区预览。

三种作用范围具有以下强制边界：

### 4.1 智能读取页面

将快捷方式提示词发送给 Agent，并提供现有完整浏览器工具集。Agent 可以按需读取
页面，也可以在现有确认闸门保护下执行页面操作。

### 4.2 选中的文字

执行前读取当前选区。没有选中文字时显示错误，不创建对话消息。选区正文最多保留
现有上限 4000 个字符，并通过明确的数据边界与 JSON 转义附加到提示词中；隐藏
提示明确声明选区属于不可信网页数据，只能作为待处理内容，不能作为指令执行。

该回合向 Agent 传入空工具列表，确保它只能处理选区和用户配置的提示词，不能
另外读取或操作页面。

### 4.3 无需页面内容

只发送用户配置的提示词，并向 Agent 传入空工具列表。对应的回合系统提示明确说明
当前任务不使用浏览器上下文。该模式不会读取或操作当前页面。

## 5. 双语行为

- 未编辑内置项的名称、提示词和作用范围展示文字随当前已解析界面语言变化。
- 用户保存对内置项的编辑后，名称和提示词固定为保存时的文本。
- 自定义项始终显示用户保存的原文，不进行自动翻译。
- “恢复默认”补回的内置项重新使用自动双语文本。
- 设置页按钮、字段、验证错误、“更多”菜单和作用范围名称全部进入现有中英文
  字典。

## 6. 实时更新与并发

快捷方式模块监听对应 `chrome.storage.local` 键的变化。Options 页面或侧边栏
内嵌设置保存后，聊天界面立即重新加载并解析快捷方式。

写操作始终基于最新已读取数组生成完整的新数组并一次性保存。单次页面中的新增、
编辑、删除和排序串行执行，保存期间禁用重复提交。已经启动的 Agent 回合只使用
点击瞬间的快照，不订阅后续配置变化。

## 7. 错误处理

- 无选区：提示先在页面中选择文字，不创建消息，不启动 Agent。
- 配置校验失败：阻止保存并定位到对应字段。
- 存储读写失败：展示错误，保留表单与当前内存列表，不声称保存成功。
- 损坏记录：设置页显示配置错误；侧边栏不执行该记录。
- 执行时记录已被删除：只要点击时已取得有效快照，本轮继续完成。
- Provider 缺失、API Key 缺失、停止生成和模型调用失败：沿用现有 `runAgent`
  错误处理。

## 8. 测试与验收

自动化测试覆盖：

- 存储键不存在时生成并持久化两个默认项；
- 存储为空数组时不重新生成默认项；
- 未编辑内置项按当前语言解析名称和提示词；
- 编辑内置项后固化文本；
- 新增、编辑、删除和排序不破坏稳定 ID 与数组顺序；
- 恢复默认只追加缺失内置 ID，不覆盖现有项；
- 损坏记录无法执行且不会被静默改写；
- 三种作用范围生成正确的 Agent 输入与工具列表；
- 选区为空时中止，长选区按 4000 字符截断，并保留不可信数据边界；
- 聊天界面展示前 3 项，其余进入“更多”，空数组时隐藏快捷入口；
- Options 设置页、侧边栏内嵌设置和聊天 store 使用统一快捷方式模块；
- 中英文字典键集合保持一致。

完成实现后运行：

- 相关定向 Vitest；
- 全部 Vitest；
- TypeScript 类型检查；
- Chrome MV3 生产构建。

手动验收覆盖：

- 中英文切换下未编辑默认项自动变化，已编辑项保持原文；
- 新增、编辑、删除、拖动排序、上移、下移与恢复默认；
- 打开的侧边栏在设置保存后实时更新；
- 前 3 项与“更多”菜单在窄侧边栏中无溢出；
- 三种作用范围分别验证页面工具可用、选区隔离和无页面工具；
- 深色与浅色主题下设置页和侧边栏显示正常。
