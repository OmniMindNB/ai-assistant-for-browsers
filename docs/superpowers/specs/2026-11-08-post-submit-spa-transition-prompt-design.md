# 提交后 SPA 软转场：提交结果核验的提示词指引 — 设计文档

- 日期：2026-11-08
- 状态：已评审（随轨迹分析确认，问题清单第 ③ 项；修法为提示词两句话，纯提示层）
- 来源轨迹：`runi-请答题-20261108-1734.md`（v1.9.1，wj.qq.com，步骤 8–13）

## 1. 背景

模型点完「提交」（步骤 8）之后，wj.qq.com 这类单页应用做了一次**软转场**：地址不变、
React 把问卷换成结束页。点击结果给它的全部信号是——

```
页面新出现 56 个可交互元素：f177「A. 施耐庵」（radio）…（其实是同一批题目被重渲染，见问题 ④）
[页面位置] 地址未变化，仍为 "https://wj.qq.com/s2/…"；无需再确认。单页应用可能只更新了局部内容。
```

——没有任何「提交是否成功」的信息，也没有「该怎么核验」的指引。模型的后续行为：

| 步骤 | 调用 | 结果 |
|---|---|---|
| 9 | `find_text "提交成功"`（猜的成功文案） | 命中 0 个 |
| 10 | `wait_for domIdle` | 等到了 |
| 11 | `find_text "答卷"`（换一个猜） | 命中 0 个 |
| 12 | `read_page` | **终于**看到「考试结束」 |
| 13 | `report_task_outcome success` | 正确 |

步骤 9–11 共 3 轮模型往返全是浪费：`find_text` 命中 0 只说明**页面上没有你猜的那句话**
（实际文案是「考试结束」，不是「提交成功」也不是「答卷」），不代表提交失败。系统提示
里没有任何提交后核验的指引，模型自然退化为「猜文案碰运气」。

## 2. 方案

`FORM_WORKFLOW` 增加第 13 条（与第 12 条「提交前核验」呼应，两句话）：

1. **提交后不要用 find_text 猜文案核验结果**：单页应用提交后通常不跳地址，点击结果只会说
   「地址未变化」；0 命中只说明页面上没有你猜的那句话，不代表提交失败。
2. **直接 read_page 看页面现在实际显示什么**，以它为准判断提交结果。

位置选择 `FORM_WORKFLOW` 而非 `task_execution`：这是表单流程「提交之后」的一环，与第 12 条
（提交之前）正好成对；它也只在涉及表单的任务里占预算。

## 3. 测试

`system-prompt.test.ts` 钉第 13 条的两个关键句（「0 命中只说明页面上没有你猜的那句话」/
「以页面实际显示」与「browser_read_page」）。

## 4. 非目标（记录不做的）

- **点击结果附加「提交后转场内容」**：`[页面位置]` 注记已如实说明地址未变；往工具结果里塞
  提交后页面摘要与既有「[跳转后页面]」机制重叠且成本高——模型按指引自己读一次即可。
- **「新出现 56 个元素」的误导措辞**：那是问题 ④（同一批题目被 React 重渲染、按身份继承后
  应报「仍在原页面」而非「新出现」），另行处理。
- **轨迹录制 target 质量**：问题 ⑤，另行处理。
- **结构性提交成功检测**（读 URL/文本模式判断「提交成功了吗」）：页面差异太大，没有可靠的
  无启发式信号，刻意不做——核验责任留给模型，指引只教方法。
