# 快捷动作回复语言设计

日期：2026-07-28

## 背景

Aluminum 已支持中文与英文界面，但侧边栏的 `Summarize page` 和
`Explain selection` 只本地化了展示文字。两项快捷动作发送给模型的隐藏提示词仍
硬编码为中文，因此英文界面下也会稳定得到中文回复。

## 目标

- `Summarize page` 和 `Explain selection` 的回复语言跟随当前已解析的界面语言。
- 中文界面发送中文快捷提示词并要求用中文回答。
- 英文界面发送英文快捷提示词并要求用英文回答。
- 普通输入框对话继续根据用户输入语言回答，不强制跟随界面语言。

## 非目标

- 不修改全局 Agent 系统提示词的语言策略。
- 不改变快捷动作的展示消息、选区截断上限、页面读取流程或会话持久化格式。
- 不为除中文和英文以外的语言增加新的回复策略。

## 设计

在现有 `lib/i18n/locales/zh.ts` 与 `lib/i18n/locales/en.ts` 中增加两个快捷提示词
翻译键：

- 页面总结提示词；
- 解释选区提示词前缀。

`entrypoints/sidepanel/store.ts` 不再内联中文提示词，而是通过模块级 `t()` 读取
当前界面语言对应的隐藏提示词。总结提示词明确要求模型用对应语言给出 3–5 个
要点和简短摘要。解释提示词明确要求模型用对应语言解释，并继续在后面附加按
`MAX_SELECTION_CHARS` 截断的原始选区文本。

普通 `send()` 与 `editMessage()` 继续把用户文字原样传给 `runAgent()`，不插入
界面语言指令，因此普通对话行为不变。

## 数据流

1. `LocaleProvider` 在用户选择语言时调用 `applyLocale()`。
2. `applyLocale()` 更新 i18n 模块的 `currentLocale`。
3. 用户触发快捷动作时，Zustand store 调用 `t()` 取得当前语言的隐藏提示词。
4. `runAgent()` 把本地化提示词发送给模型；界面仍显示本地化后的动作标签。

## 测试

将快捷提示词组装提取为 `lib/` 下的纯函数，以便使用现有 Vitest 配置测试真实
行为。回归测试覆盖：

- `en` 总结提示词为英文并明确要求英文回答；
- `zh` 总结提示词为中文并明确要求中文回答；
- `en` 与 `zh` 的解释提示词均保留选中文本；
- 过长选区仍按现有上限截断；
- 普通对话路径不使用该快捷提示词组装函数。
