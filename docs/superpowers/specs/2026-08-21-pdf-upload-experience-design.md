# 设计：PDF 上传与附件体验优化

- 状态：已批准 Approved
- 日期：2026-08-21
- 前置设计：`2026-08-21-file-upload-attachment-design.md`
- 关联：`lib/chat/attachments.ts`、`lib/chat/messages.ts`、`lib/db.ts`、
  `entrypoints/sidepanel/store.ts`、
  `entrypoints/sidepanel/components/WorkbenchComposer.tsx`、
  `entrypoints/sidepanel/components/AttachmentChip.tsx`

## 1. 背景

现有附件功能支持文本文件与图片，但明确排除了 PDF、Word 等需要额外解析能力的
格式。用户需要在不把原始文件交给第三方解析服务的前提下，把普通 PDF 作为当轮
对话上下文；同时希望附件区域保持紧凑，并对解析进度、拖放、错误和重试提供清晰
反馈。

本设计扩展既有的“附件仅作用于当前轮”语义。PDF 的提取正文只在待发送阶段存在于
侧栏内存，发送时作为不可信参考资料进入当轮提示词，之后不进入历史重放，也不写入
IndexedDB。历史消息只保留足以回看的附件元数据。

## 2. 目标

- 支持通过回形针按钮选择 PDF，也支持把 PDF 拖到输入框区域。
- 在浏览器扩展内使用本地解析器提取 PDF 文字，不上传到远程解析服务。
- 单个 PDF 最大 20 MB；单个 PDF 最多提取 60,000 个字符。
- 解析期间立即显示轻量状态芯片并禁用发送。
- 清晰展示成功、截断和错误状态；失败附件不阻塞其他正常内容发送。
- PDF 正文和原始字节不持久化，只保存文件元数据。
- 解析在 Worker 中执行，避免较大 PDF 阻塞侧栏交互。
- 不增加浏览器权限，不使用 CDN 或其他远程运行时代码。

## 3. 非目标

- 不做扫描版 PDF 的 OCR；没有可提取文字时给出明确错误。
- 不支持 Word、Excel、PowerPoint 或其他办公格式。
- 不渲染 PDF 页面缩略图或内嵌 PDF 阅读器。
- 不向模型 Provider 直接发送 PDF 原文件。
- 不为加密或密码保护 PDF 提供密码输入。
- 不让附件跨轮复用，也不支持编辑历史消息时重新递送附件。
- 不预先计算 PDF 的 token 数；字符上限是首期唯一的内容体积边界。

## 4. 方案选择

### 4.1 采用：PDF.js + 独立 Worker

新增 `pdfjs-dist` 依赖，在侧栏内读取 `ArrayBuffer`，由 PDF.js Worker 打开文档并逐页
提取文字。Worker、CMap、标准字体及解析所需的其他静态资源随扩展本地打包。

选择理由：

- PDF.js 是成熟的浏览器 PDF 解析实现，支持从二进制数据加载文档并逐页读取内容。
- Worker 可把较重的解析工作移出侧栏主线程。
- 本地静态资源符合 Manifest V3 的远程代码限制和项目的本地优先原则。
- 当前需求只需要文字提取，无需引入完整查看器或更重的 WASM 文档引擎。

参考：

- [PDF.js 浏览器示例](https://mozilla.github.io/pdf.js/examples/)
- [PDF.js Worker API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFWorker.html)
- [WXT 静态资源说明](https://wxt.dev/guide/essentials/assets)

### 4.2 未采用：主线程运行 PDF.js

接入路径较短，但解析接近 20 MB 或页数较多的文档时可能阻塞输入框和状态更新，与本次
体验目标冲突。

### 4.3 未采用：MuPDF/WASM 等其他引擎

这类引擎可能提供更强的容错或渲染能力，但会增加扩展体积、WASM 资源管理和维护成本；
首期的纯文本提取不需要这些能力。

## 5. 类型与模块边界

### 5.1 持久化附件

历史消息继续使用 `MessageAttachment`，但 PDF 记录只包含展示元数据：

```ts
interface PdfAttachmentMetadata {
  id: string;
  name: string;
  mimeType: 'application/pdf';
  size: number;
  kind: 'pdf';
  pageCount: number;
  extractedChars: number;
  truncated: boolean;
}
```

该结构没有正文、`ArrayBuffer`、Blob URL 或 Worker 句柄。现有文本和图片附件的历史
结构保持兼容。

### 5.2 待发送附件

输入框使用单独的 `PendingAttachment` 联合类型表示生命周期：

- `parsing`：包含稳定 ID、文件元数据、任务 ID 和可选页级进度；
- `ready`：包含历史元数据以及仅在内存存在的提取正文；
- `error`：包含稳定错误原因、是否允许重试，以及重试所需的当前会话内 File 引用。

所有待发送附件共享相同的稳定 ID，状态变化不替换 ID，避免芯片重挂载和焦点跳动。
PDF 的临时字段不能通过 `toMessageRecords` 进入数据库。

### 5.3 PDF 解析模块

新增聚焦的纯解析边界，例如 `lib/chat/pdf-extractor.ts`：

```ts
interface PdfExtractionResult {
  text: string;
  pageCount: number;
  extractedChars: number;
  truncated: boolean;
}

interface PdfExtractionOptions {
  maxChars: number;
  signal: AbortSignal;
  onProgress?: (completedPages: number, pageCount: number) => void;
}
```

模块负责 PDF 文件头校验、PDF.js 初始化、逐页文字提取、页分隔、字符上限、取消和底层
异常归一化。Store 不依赖 PDF.js 的具体异常类型；UI 也不直接调用解析器。

## 6. 数据流

1. 用户通过文件选择器或拖放添加文件。
2. Store 在任何异步读取开始前同步预留附件名额，保证总数不超过 5 个。
3. 文件先经过类型、20 MB 上限和 `%PDF-` 文件头校验。
4. 合法 PDF 立即进入 `parsing` 状态，UI 显示文件名、进度和移除按钮。
5. 调度器最多同时运行 2 个 PDF 解析任务，其他任务保持排队状态。
6. PDF.js 打开二进制数据并逐页调用文字内容提取；页与页之间加入稳定的页分隔，避免
   相邻页面内容粘连。
7. 累计文字达到 60,000 字符后停止继续提取，保留前 60,000 字符并标记
   `truncated: true`。
8. 成功任务进入 `ready`；没有可用文字或发生错误的任务进入 `error`。
9. 只要存在 `parsing` 或排队中的附件，发送按钮保持禁用。
10. 发送时，Store 只收集 `ready` 附件。PDF 正文使用现有附件模板的安全边界包装为
    “不可信参考资料”，与用户文字一起进入当轮提示词。
11. 发起本轮后，显示消息只接收 `PdfAttachmentMetadata`；原始字节和正文从待发送状态
    清除，不能落库。
12. 后续轮次从历史恢复时只显示只读芯片，不重新向模型递送 PDF 内容。

## 7. 交互与视觉

### 7.1 布局

沿用现有轻量附件芯片，不新增常驻投放面板或大尺寸文件卡片。PDF 芯片位于输入框上方
的现有附件行，可以与文本文件和图片混排并自动换行。

### 7.2 状态

- **排队/解析中**：旋转状态图标、文件名、页级百分比或“准备解析”，以及移除按钮。
- **成功**：确认图标、文件名和页数。
- **已截断**：警示图标和“已截断”；补充说明明确最多提取 60,000 字符。
- **错误**：红色错误芯片，显示简短原因、移除按钮，以及在适用时显示“重试”。

损坏或临时读取失败可重试；超限、加密和无可提取文字不显示重试。

### 7.3 拖放

回形针按钮继续作为稳定入口。文件拖入输入框区域时：

- 输入框使用轻量强调色边框和背景；
- 占位文字临时变为“松开即可添加 PDF”；
- 离开或释放后清除高亮；
- 只接管包含文件的拖放，不影响普通文字拖放和输入框选择行为。

### 7.4 发送门禁

- 存在排队或解析中的附件时禁用发送。
- 错误附件不计入发送内容，也不阻塞文字或其他正常附件。
- 如果输入为空且只有错误附件，则不能发送空消息。
- 用户可在解析期间移除附件；最后一个未完成附件被移除后立即恢复正常发送条件。

## 8. 错误处理与并发安全

稳定错误类别包括：

- `too-large`：超过 20 MB；
- `invalid-pdf`：文件头不合法或 PDF 损坏；
- `password-protected`：需要密码或加密方式不受支持；
- `no-extractable-text`：文档打开成功但没有可用文字；
- `read-failed`：浏览器读取文件失败；
- `parse-failed`：其他 PDF.js/Worker 解析错误。

错误附件保留在附件行，直到用户移除；它不写入已发送消息，也不进入提示词。

每个解析任务持有独立任务 ID 和 `AbortController`。移除附件、清空输入状态、切换或删除
会话、销毁侧栏文档时都取消任务。回调提交结果前必须同时校验附件 ID、任务 ID 和当前
会话来源；任何迟到结果都被丢弃。

解析并发上限固定为 2。排队项被移除后不启动；运行项结束或取消后再启动下一项。附件
数量限制在异步边界之前原子预留，避免多个并发 `addAttachmentFiles` 调用突破 5 个上限。

## 9. 隐私与安全

- PDF 原始字节只交给扩展本地的 PDF.js Worker。
- Worker、CMap、字体及其他运行资源随扩展包发布，不从网络加载。
- 不增加 host、scripting 或文件系统权限。
- 只有提取出的正文在用户发送消息时进入当前 Provider 请求。
- PDF 正文和原始字节不进入 IndexedDB、`chrome.storage`、日志或错误文案。
- 文件名和提取正文都按不可信数据处理，不允许影响模板边界或系统指令。
- 解析错误只展示归一化的用户文案，不直接暴露 PDF.js 堆栈或内部路径。

## 10. 测试与验收

### 10.1 自动化测试

- 文件分类、MIME/扩展名兼容、20 MB 上限和 PDF 文件头校验。
- 多页 PDF 的文本顺序、稳定页分隔和页数统计。
- 恰好达到及超过 60,000 字符时的截断行为。
- 空白/扫描版、损坏、加密 PDF 的错误映射。
- 最多 2 个并行任务和最多 5 个附件的调度边界。
- 移除、清空、切换会话后的取消与迟到结果隔离。
- 解析期间禁用发送；失败附件不阻塞其他正常内容。
- 只有错误附件且没有文字时不能发送。
- PDF 持久化投影只含元数据，不含正文、字节或任务状态。
- 拖入、拖离、释放、重试、移除和键盘焦点行为。
- 中英文状态、错误和无障碍标签。

测试 PDF 使用仓库内最小固定夹具或在测试中生成的确定性字节，避免网络依赖和大型二进制
文件。PDF.js 边界通过小型适配器注入或 mock，调度和 store 竞态测试不依赖真实 Worker。

### 10.2 构建与人工验收

- 运行完整测试、TypeScript 类型检查和 Chrome MV3 生产构建。
- 检查扩展产物包含 Worker、CMap、字体和所需静态资源，且没有远程运行时代码。
- 使用中文 PDF、英文 PDF、接近 20 MB 的长文档、扫描件、加密文档和损坏文件测试。
- 混合上传文本、图片和 PDF，确认总数上限和单轮提示词正确。
- 在解析中移除附件、切换会话、清空会话并重新打开历史消息。
- 在浅色、深色和窄侧栏下检查芯片换行、错误可读性和键盘焦点。

## 11. 完成标准

- 含可提取文字的普通 PDF 能稳定作为当轮上下文使用。
- 20 MB 和 60,000 字符限制在 UI 与逻辑层保持一致。
- 解析期间侧栏保持响应，发送门禁不存在竞态。
- 拖放、状态、错误、重试和移除反馈清晰且紧凑。
- PDF 正文和原始字节不会出现在任何持久化记录中。
- 现有文本与图片附件行为不回退。
- 自动化测试、类型检查和生产构建全部通过。
