# 侧边栏上下文工作台重设计

日期：2026-07-30

## 背景

Aluminum 当前把会话列表、模型选择、快捷指令、聊天消息、Agent 工具状态、操作确认、
撤销入口和完整设置放在同一个侧边栏层级。功能已经完整，但在浏览器侧边栏常见的
窄宽度下，信息层级偏平，空白页和输入区承担过多入口，内嵌设置尤其容易形成连续
长表单。

本设计参考三类浏览器 AI 产品的公开交互模式：

- Perplexity Comet Assistant：持续显示当前网页上下文，并在浏览过程中保持助手可用；
- Claude for Chrome：把网页操作过程、权限确认和安全状态放在对话任务流中；
- Tabbit：把上下文引用、模型选择和技能调用集中到统一输入入口。

Aluminum 不复制这些产品的视觉样式，而是结合现有的本地优先、多 Provider、逐轮确认
和一键撤销能力，重组为“上下文工作台”。

## 目标

- 同时优化页面问答、总结和 Agent 网页操作体验。
- 当前网页上下文、工作模式和执行状态始终清晰可见。
- 统一输入区承载上下文、模型和快捷指令调用，减少独立工具条。
- 会话历史按需展开，不长期挤占聊天宽度。
- 把完整配置迁移到独立 Options 设置页，消除侧边栏内嵌长设置。
- 保留现有 Agent、Provider、快捷指令、会话持久化、确认和撤销语义。
- 支持窄侧边栏、浅色与深色主题、中英文界面和键盘操作。

## 非目标

- 不新增第二套 Agent 引擎或不同的工具权限模型。
- 不改变 Provider、快捷指令和 Dexie 会话记录的持久化格式。
- 不增加跨标签页上下文、文件上传、工作区或任务并行能力。
- 不重写 Options 中已有设置表单的业务逻辑。
- 不引入新的远程服务、遥测或云同步。
- 不在本轮重设计浏览器页面本身、扩展弹窗或 Chrome Web Store 素材。

## 1. 设计方向

采用“上下文工作台”而不是极简聊天布局。工作台由五个稳定区域组成：

1. 顶部栏；
2. 当前网页上下文；
3. 问答 / 执行任务模式；
4. 对话与 Agent 状态时间线；
5. 统一输入区。

布局在日常问答和 Agent 执行间保持稳定，只改变中部内容和输入提示，避免用户启动
任务后面对一套完全不同的界面。

视觉层级使用中性背景、轻边框和少量强调色。强调色只用于当前选择、主要操作和运行
状态，不给每个普通组件增加彩色边框或独立卡片。

## 2. 侧边栏信息架构

### 2.1 顶部栏

顶部栏只保留：

- Aluminum 标识；
- 新建会话；
- 打开会话历史；
- 更多菜单。

更多菜单提供完整设置、主题快速切换和清空当前会话等低频操作。完整设置使用
`browser.runtime.openOptionsPage()` 打开独立 Options 页面，不再切换侧边栏内部
`settings` 视图。

### 2.2 当前网页上下文

顶部栏下方常驻单行网页上下文条，显示网站图标、页面标题和连接状态。点击后展开
当前回合会使用的上下文说明；本轮只支持当前标签页，不暗示尚未实现的多标签页引用。

页面标题截断时保留完整无障碍名称。受限页面、标签页不可用或内容提取失败时，该区域
显示明确状态，并提供重试或继续无页面上下文对话的入口。

### 2.3 工作模式

网页上下文下方提供两个模式：

- 问答：突出总结、解释、提取信息等只读任务；
- 执行任务：突出点击、填写、修改页面和导航等 Agent 行为。

两个模式复用同一个 Agent 和工具权限系统。模式只改变空白页建议、输入提示、默认
快捷动作和执行状态表达，不绕过现有确认闸门，也不限制用户在自然语言中提出另一类
任务。

默认模式可以在设置页配置。模式属于当前会话的界面状态，不修改现有消息持久化格式；
重新打开既有会话时使用用户默认模式。

### 2.4 对话与 Agent 时间线

消息、工具执行、确认和撤销按发生顺序显示在同一时间线：

- 用户和助手消息继续使用现有消息组件；
- 多个工具活动合并为单个 Agent 活动卡片；
- 活动卡片显示当前步骤、完成数和失败步骤，可展开查看工具明细；
- 首次写操作的确认卡片紧邻对应活动卡片；
- 完成写操作后，撤销入口保留在本轮结果附近，直到下一轮开始；
- 停止、失败和被拒绝均在原活动卡片上转为终态，不额外堆叠重复提示。

长代码、工具参数和确认摘要保持可滚动或折叠，避免撑宽侧边栏。

### 2.5 空白状态

空白状态不再重复展示模型、快捷指令和输入框已有的控制。它只包含：

- 当前模式对应的一句引导；
- 最多四个高频建议；
- Provider 未配置时的单一设置入口。

建议动作来自现有快捷指令解析结果。没有快捷指令时使用最小的内置引导，不在运行时
重新写入用户配置。

## 3. 统一输入区

输入区固定在侧边栏底部，包含：

- 可自适应高度的文本输入；
- 上下文入口；
- 当前 Provider / 模型入口；
- 快捷指令入口；
- 发送或停止按钮。

快捷指令统一通过输入 `/` 或点击快捷入口搜索调用，不再把前三项长期铺在输入框上方。
菜单按名称和命令过滤，键盘可完成打开、选择和关闭。

当前网页默认附加，但用户可在单次发送前移除。模型入口只负责快速切换已经配置好的
模型；添加服务、API Key、连接测试和模型列表编辑全部进入独立设置页。

输入区保持现有 Enter 发送、Shift+Enter 换行和 busy 状态。上下文或 Provider
不可用时，发送按钮不静默失败，而是在输入区附近显示可操作的错误说明。

## 4. 会话历史

会话历史改为从侧边栏左侧覆盖展开的抽屉。打开时刷新本地会话列表，关闭后聊天区域
恢复完整宽度。

抽屉包含：

- 新建会话；
- 本地会话搜索；
- 按“今天、昨天、更早”分组的会话列表；
- 当前会话状态；
- 删除操作。

搜索只匹配已加载的本地标题，不新增全文索引。删除继续使用现有删除语义，并在真正
删除前确认。窄宽度下抽屉覆盖聊天；较宽宽度下仍保持覆盖模式，避免形成永久双栏。

## 5. 独立设置页

Options 页面使用固定左侧分组导航和右侧单主题内容区：

- 偏好：通用、外观、语言；
- AI 与工具：模型服务、快捷指令；
- 安全：权限与隐私；
- 关于。

导航在窄宽度下收窄为图标加短标签或顶部选择器，内容区不得产生页面级横向滚动。
设置保存后继续通过现有 `chrome.storage.local` 变化监听实时更新已打开的侧边栏。

### 5.1 通用

通用设置只包含跨功能偏好：

- 默认工作模式；
- 是否记住每个标签页的对话；
- 是否默认附加当前网页；
- 写操作确认频率的现有可配置项；
- 完成后是否显示撤销入口。

不存在对应业务能力的选项不得只做视觉占位；若本轮实现不增加某项持久化能力，则从
首版界面移除。

### 5.2 模型服务

模型服务首页显示服务商卡片列表。每张卡片只显示名称、连接状态、模型数量、默认状态
和编辑入口。

添加或编辑服务使用独立表单视图，复用现有 Provider 字段、校验和存储逻辑。API Key
默认遮挡，连接失败保留表单输入并显示具体错误。删除服务需要确认，且不得删除后仍
把其模型留作当前选择。

### 5.3 快捷指令

快捷指令使用列表或表格管理，显示名称、调用方式、作用范围、启用状态和行级菜单。
新建和编辑进入独立表单视图，复用现有快捷指令数据模型与校验。

首版不新增文件夹、标签、图标选择或云同步。排序继续保留键盘可用的上移、下移操作；
拖动排序只有在不损害键盘能力时才保留。

### 5.4 权限与隐私

该栏目解释现有本地存储、页面读取、写操作确认和一键撤销边界，并提供可配置项的
入口。它不得声称扩展能够提供现有实现之外的安全保证。

## 6. 组件边界

`entrypoints/sidepanel/App.tsx` 当前同时承担应用编排和大量视图组件。重设计时拆出
以下聚焦组件：

- `WorkbenchShell`：侧边栏整体编排和抽屉状态；
- `WorkbenchHeader`：顶部栏与低频菜单；
- `PageContextBar`：当前网页身份和可用状态；
- `ModeSwitch`：问答 / 执行任务界面状态；
- `ConversationView`：消息时间线和自动滚动；
- `AgentActivityCard`：聚合工具步骤与终态；
- `ConfirmationCard`：现有确认数据的展示；
- `UndoBar`：现有撤销动作的展示；
- `HistoryDrawer`：会话搜索、分组和选择；
- `Composer`：输入、上下文、模型和快捷指令入口。

Options 页面使用：

- `SettingsShell`：分组导航和内容区；
- 现有 `AppearanceSettings`、`LanguageSettings`、`ProviderSettings` 和
  `ShortcutSettings` 作为业务表单；
- 必要时在现有表单外增加列表页和编辑页容器，但不复制存储逻辑。

组件通过明确 props 接收状态和动作。Zustand store 继续拥有会话、Agent 和 Provider
运行状态；纯展示状态如抽屉开关、菜单开关和当前设置栏目保留在组件本地。

## 7. 数据流

1. 侧边栏启动时继续刷新 Provider、快捷指令和会话，并恢复当前标签页会话。
2. 当前标签页变化后，`PageContextBar` 从现有标签页绑定结果派生展示状态。
3. 用户在输入区选择模型时调用现有 `selectProviderAndModel`。
4. 用户调用快捷指令时继续使用现有 `runShortcut`，输入区只负责选择和提交。
5. Agent 生命周期继续写入 `messages`、`toolActivities`、`pendingConfirmation` 和
   `turnHasChanges`；新的时间线组件只组合这些现有状态。
6. Options 保存到现有本地存储；侧边栏监听变化并刷新对应配置。

本轮不增加新的跨上下文消息协议。若实现中发现当前标签页标题或受限状态无法从现有
数据可靠派生，再在实施计划中增加最小只读消息，而不是预先扩展协议。

## 8. 错误与边界状态

- Provider 未配置：空白状态显示唯一的“打开模型设置”操作。
- API Key 或模型缺失：输入区显示具体缺失项并保留用户输入。
- 当前标签页不可访问：上下文条显示受限，允许继续无页面上下文对话。
- 页面读取失败：Agent 活动卡片显示失败步骤和重试入口。
- 写操作等待确认：输入区保持停止能力，确认卡片成为当前主要操作。
- 用户拒绝：活动卡片转为“已拒绝”，不显示误导性的失败告警。
- Agent 停止：已完成步骤保留，当前步骤标记为已停止。
- 撤销失败：撤销入口保留，并显示具体错误，不声称页面已恢复。
- 设置读取或保存失败：保留表单内容，显示错误，不关闭编辑视图。
- 损坏的快捷指令或 Provider：沿用现有验证策略，不允许从新界面执行非法记录。

## 9. 无障碍与响应式

- 所有图标按钮都有可访问名称和可见焦点。
- 模式切换、历史抽屉、菜单和快捷指令选择支持键盘操作与 Escape 关闭。
- 颜色不作为运行、失败、确认或选中状态的唯一表达。
- 侧边栏从约 320px 起不产生页面级横向滚动。
- 长标题、模型名和会话名使用单行截断，并保留完整辅助文本。
- 浅色、深色和跟随系统主题继续使用现有主题机制。
- 中文和英文字典保持键集合一致。

## 10. 测试与验收

自动化测试覆盖：

- 当前网页上下文的可用、受限和失败状态映射；
- 问答 / 执行任务模式切换不改变 Agent 权限语义；
- Agent 活动聚合后的运行、确认、完成、拒绝、停止和失败状态；
- 会话按日期分组、搜索、选择和删除；
- 模型快速切换继续调用现有 store 动作；
- `/` 快捷指令菜单过滤、选择和 busy 禁用；
- Options 分组导航；
- Provider 与快捷指令表单继续使用现有存储和验证；
- 设置保存后侧边栏刷新；
- 中英文字典键集合一致。

实现前若组件层目前缺少可测试运行环境，先增加最小的 React 测试配置，只覆盖本次
拆分组件，不顺带迁移所有旧 UI 测试。

完成实现后运行：

- 相关定向 Vitest；
- 全部 Vitest；
- TypeScript 类型检查；
- Chrome MV3 生产构建。

手动验收覆盖：

- 320px、360px 和较宽侧边栏下无溢出；
- 空白问答、已有对话、Agent 执行、等待确认、完成并可撤销等关键状态；
- 会话抽屉打开、搜索、切换和删除；
- 模型切换和快捷指令 `/` 调用；
- 独立设置页各栏目、表单保存和错误保留；
- Provider 或页面上下文缺失时的恢复路径；
- 浅色、深色、中英文和键盘导航。
